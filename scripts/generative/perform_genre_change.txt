# A genre change mid-piece (#217, spec §9.7, §13.6, §14.1) over the sysex test port: GENRE ▸ opens on the playing
# genre's row (TECHNO ▸) and its submenu on the playing subgenre (ACID, = REGEN). Picking the sibling (MELODIC, Melodic
# techno, 5 parts where Acid techno has 4) asks MELODIC TECHNO? on DROP and plays the transition.
# Then back to ACID with a hard cut, from the other roster size, on to DUB (Dub techno, 5 parts, its Stab and Pad live
# for the H1 after it) and to DETROIT (Detroit techno, 6 parts, the largest roster, its Strings, Stab and walk live for
# the H1 after it), each with a hard cut, so the change visits all four, and back to ACID. Runs on a Deluge
# (deluge_probe.py session) or in delugemu (test_port_emu.py). Start as after boot: transport stopped, the current clip a
# synth or kit clip.
#
# gen_confirm <genre name> style=<0 drop|1 fade|2 cut> result=<0 started|1 refused|2 queue full|3 ignored|4 busy>
# working=<0|1>, gen_confirm regenerate for the genre playing. gen_transition_preload done parts=N ms= is the
# preload time for the incoming roster.
# gen_mem before_transition and after_free give the heap balance across each change (both rosters' sizes).
# gen_outputs_freed outputs=N total=M: the Outputs one free job freed, and every Transition-owned Output freed since
# none was left retiring, however its batches fall: the outgoing roster's, and a cancelled preload's incoming roster's
# too (here no preload is cancelled, so it is the outgoing roster's). After each total= the script marks and
# later expects no further gen_outputs_freed since the mark: a batch reaching the total with an Output still to come
# fails. Each genre is picked by name (pick genre).
# For figures: --events 'gen_confirm|gen_transition|gen_mem|gen_h1|gen_outputs_freed'.
# covers: src/deluge/gui/views/perform_view.cpp src/deluge/gui/views/perform_view.h
# covers: src/deluge/gui/views/perform_view_internal.h src/deluge/generative/firmware/transitions.*
# covers: src/deluge/generative/perform/transition_lifecycle.h src/deluge/generative/firmware/retirements.*
# covers: src/deluge/generative/firmware/pump.* src/deluge/generative/firmware/runner.* src/deluge/generative/runner/
# covers: src/deluge/generative/core/ src/deluge/gui/context_menu/generative.*
# covers: src/deluge/gui/menu_item/generative/genre_rows.* src/deluge/generative/perform/genre_menu.*
# covers: src/deluge/generative/perform/perform_driver.* src/deluge/generative/firmware/current_recipe.*
# covers: src/deluge/generative/firmware/perform_song.* src/deluge/generative/firmware/adapter_timing.*
# covers: src/deluge/gui/views/perform_view_knobs.cpp src/deluge/generative/firmware/entry_leave.cpp

start_state
include perform_open.txt
include perform_confirm.txt
button PLAY down
wait 50
button PLAY up
expect playing=true
expect event gen_section INTRO 0

# ---- TECHNO ▸ MELODIC → DROP (the default): 4 parts to 5 ----
# Perform menu at its top row, GENRE; GENRE opens on TECHNO ▸, which opens on ACID (= REGEN); pick MELODIC by name
mark
include perform_transition_menu.txt
button SELECT_ENC down
wait 50
button SELECT_ENC up
wait 200
pick genre techno-melodic
expect event gen_genre_pick techno-melodic row=TECHNO
button SELECT_ENC down
wait 50
button SELECT_ENC up
wait 200
pick genre techno-melodic
expect event gen_genre_pick techno-melodic row=MELODIC from=ACID
button SELECT_ENC down
wait 50
button SELECT_ENC up
expect ui=sound_editor
expect event gen_regen_page open
button SELECT_ENC down
wait 50
button SELECT_ENC up
expect event gen_transition phase=preloading
expect event gen_confirm techno-melodic style=0 result=0
expect event gen_transition_preload done error=0 parts=5 within=20
# The Pad's .volume = 50 reaches the level it plays at (the patcher's), not only the knob (#228)
expect event gen_sound_level PAD volume=50 lower since=mark
expect event gen_transition phase=queued
expect event gen_transition phase=committed within=60
# Acid's BUILD variant set includes long (16 or 32 bars, #531): a 32-bar Build gliding 125 -> 122 BPM takes up to
# 62.2 s in real time (#561), and up to ~3x that in host seconds under delugemu load.
expect event gen_transition start style=0 within=180
expect event gen_transition phase=retiring
expect event gen_focus part=-1 locked=-1 new_roster
# Acid's 4 Outputs retire after their tails: in one batch, or 3 and then the Drone once its release ends; total= counts
# them all, however the batches fall.
expect event /^gen_outputs_freed outputs=\d+ total=4$/ within=40
mark
expect event gen_mem after_free
expect event gen_transition phase=idle within=10
expect playing=true
expect event gen_h1 steps= within=20
expect no_event gen_outputs_freed since=mark within=2
