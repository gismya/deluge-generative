# Chainload check (#166). When this firmware started after a loadfw, no DMA channel of the firmware that loaded it may
# still have been running: those channels re-read link descriptors from memory the new image overwrites.
# On the Deluge this holds once the firmware doing the load has #166's fix (dmaStopAllChannels() before the copy in
# chainload_from_buf()). A load from an older build, such as an SD-flashed one from before the fix, fails here and
# lists the channels that ran on, or stopped on an error (boot_dma_channel lines); resetprg() stops them, but they ran during the copy.
# delugemu doesn't chainload, so there it always passes: it is a hardware-only check, which check_all.py doesn't run
# (it runs perform_*.txt and test_port_smoke.txt). Put it first in a hardware session that loads a build
# (deluge_probe.py session --build ... test_port_boot_dma.txt ...): it reads what the load left.
# runs-via: deluge_probe.py session --build ... (hardware only: first in a session that loads a build)
report boot_dma
expect event boot_dma running=0
